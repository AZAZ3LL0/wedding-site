# CLAUDE.md

Свадебный сайт-приглашение плюс Telegram-бот. SvelteKit, TypeScript, Drizzle, PostgreSQL, pg-boss, grammY.

## Источник истины

`tech.md` в корне репозитория. Прочитай его целиком перед первым изменением кода в сессии и подчиняйся дословно: стек, структура папок, схема БД, контракты очереди, общие типы, контент-конфиг, UI-примитивы, доктрина тестов, конвенции.

При расхождении между `tech.md` и тем, что уже лежит в коде, останови работу и сообщи о расхождении. Не подстраивай контракт под код.

## Контракты не выдумывать

Нужного типа, поля, топика или payload нет в `tech.md`: СТОП. Не писать код с выдуманным типом, не добавлять поле в схему БД, не расширять `lib/types` по своей инициативе. Выдать блок:

```
CONTRACT GAP
Нужно: <что именно>
Зачем: <какая задача блокируется>
Предлагаемая форма: <тип, поле, payload>
Затрагивает: <файлы и слайсы>
```

Дальше работать на локальной заглушке и ждать обновления `tech.md` с бампом версии. `tech.md` из рабочей сессии не редактировать.

## Рабочий режим

- Одна задача из раздела 13 `tech.md` за раз. Сфокусированный дифф, не вываливать всё приложение.
- Каждая задача равна одному вертикальному слайсу и одному PR: домен в `lib/server/<домен>` плюс его роут плюс локальные компоненты.
- Новый слайс повторяет структуру эталонного слайса `src/routes/(site)/rsvp`. Свою раскладку не изобретать.
- Тексты берутся из `src/lib/content/wedding.ts`. Строк с контентом в компонентах нет.
- UI собирается из примитивов `src/lib/ui`. Своя кнопка или своё поле ввода вместо примитива запрещены.
- Миграции генерируются через `drizzle-kit generate` из `src/lib/server/db/schema.ts`. Файлы в `drizzle/` руками не править.

## Тесты

Выводятся из критериев приёмки задачи, не из реализации. Тест кодирует контракт.

Обязательно на слайс: контрактный тест на стыке, тест идемпотентности на каждый хендлер pg-boss (два прогона с одним payload дают ровно один эффект), тест пути ошибки через фейковый клиент, property-based (fast-check) на чистой доменной логике. PR без них не проходит гейт.

## Команды

```
pnpm dev
pnpm check          # svelte-check
pnpm lint
pnpm test           # vitest
pnpm test:e2e       # playwright
pnpm db:generate    # drizzle-kit generate
pnpm db:migrate
pnpm db:seed        # scripts/seed.ts
pnpm build
```

Разработка идёт с `USE_FAKE_TELEGRAM=true`. Реальный токен бота для локальной работы не нужен.

## Коммиты и PR

Английский язык. Conventional Commits `type(scope): summary`, `type` из `feat|fix|test|refactor|chore|docs`, императив, строчная буква, без точки, до 50 символов. Коммитить самостоятельно по ходу работы маленькими логическими коммитами, не одним в конце. Комментарии в коде объясняют почему, а не пересказывают код. Закомментированный код в PR не оставлять.
